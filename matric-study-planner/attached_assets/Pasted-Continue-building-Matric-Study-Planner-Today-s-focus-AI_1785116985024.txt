Continue building "Matric Study Planner". Today's focus: AI-POWERED SCHEDULE GENERATOR — replace the simple weighted round-robin task logic from Day 3 with real AI-generated study plans.

CONTEXT: Dashboard currently generates "today's tasks" using basic weighted distribution logic. We're upgrading this to call an AI model that generates a smarter, more personalized schedule.

TASK 1: BACKEND SETUP
- Create a minimal Express server (/server/index.js) with one endpoint: POST /api/generate-schedule
- Use environment variable for the API key (process.env.ANTHROPIC_API_KEY) — set this up in Replit Secrets, never hardcode it
- Install @anthropic-ai/sdk on the backend
- The frontend calls this backend endpoint (not the AI API directly) — never expose the API key to the browser

TASK 2: SCHEDULE GENERATION ENDPOINT
The endpoint receives:
{
  subjects: [{ name, totalChapters, completedChapters, chapterList: [{name, done}] }],
  daysLeft: number,
  currentMode: 'fun' | 'balanced' | 'focus',
  studyHoursPerDay: number (default 3 if not provided)
}

It should call the AI model with a system prompt like:
"You are a study planning assistant for a Matric-level student in Pakistan. Given their subjects, remaining chapters, and days left until exams, generate a realistic, balanced daily study schedule for the next 7 days. Prioritize subjects with more incomplete chapters and less time. Each day should have 2-4 focused study blocks, not overwhelming. Respond ONLY with valid JSON, no markdown, no explanation, in this exact format:
{
  "week": [
    { "day": "Monday", "date": "YYYY-MM-DD", "blocks": [{ "subject": "Physics", "chapter": "Vectors", "durationMinutes": 45 }] }
  ]
}"

Pass the actual subject/chapter/daysLeft data into the user message as JSON.

TASK 3: RESPONSE HANDLING
- Parse the JSON response (strip markdown fences defensively in case model adds them)
- Store the generated 7-day plan in Context/localStorage under a key like `aiSchedule`
- Replace Dashboard's "Today's Tasks" logic: instead of the Day 3 round-robin, pull today's tasks from the matching day in `aiSchedule`
- If no AI schedule exists yet (first load, or API call fails), fall back to the Day 3 round-robin logic so the app never breaks

TASK 4: "REGENERATE PLAN" UX
- Add a button on Dashboard (or a dedicated small "Plan" section): "Regenerate My Plan" 
- Tapping it re-sends current subject/progress data to the endpoint and refreshes the 7-day schedule
- Show a loading state while waiting (skeleton or spinner, 2-5 seconds is normal for an API call)
- Show a friendly error toast if the API call fails ("Couldn't reach AI planner, using backup schedule" — don't break the app)

TASK 5: WEEKLY VIEW (new small screen or expandable section)
- Show the full 7-day AI-generated plan, not just today — a simple horizontal day-by-day list or vertical accordion
- Let the student see tomorrow's/this week's plan, not just today's tasks

- If currentMode is 'focus', adjust the system prompt to be stricter: "This student is running low on time. Be aggressive about pacing — assign more study blocks per day, prioritize ruthlessly by urgency, minimal buffer time."
